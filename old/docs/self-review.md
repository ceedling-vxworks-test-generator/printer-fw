## 3. 指摘と反映（Findings）

### F1【Major / C1・C6】O(1)アクセスの主張と実装ヒント（線形探索）の不整合
- **問題**: basic-design は「ID→index O(1)」と謳うが、detailed-design の非公開APIは線形探索＋TODO。リアルタイム性の根拠が崩れる。
- **直し方**: **データID・状態IDを 0..N-1 の稠密値に規約化**し、`index == id` の直接添字でO(1)を保証。初期化時に
  「IDが範囲内かつ重複なし」を検証（不正は `PF_ERR_INVALID_ARG`）。疎なIDが必要な場合のみ init時に索引表を構築。
- **反映**: detailed-design §3.4/§4・basic-design §5.5 に「稠密ID規約」を追記。→ 反映済。

### F2【Major / C1】Dispatch 中の購読変更（subscribe/unsubscribe）の挙動が未定義
- **問題**: コールバック内で `subscribe`/`unsubscribe` するとイテレーションが壊れうる。
- **直し方**: 規約を明文化。**自分の購読の unsubscribe は許可**（配信ループ後にスロット解放／走査は固定スナップショットのインデックスで実施）。
  **配信中の新規 subscribe は次tickから有効**。観測者テーブルの増減は `critical` で保護。
- **反映**: detailed-design §7 に「再入規約」を追記。→ 反映済。

### F3【Major / C1】Raw スナップショットの整合性コストとスレッド規約が曖昧
- **問題**: 「毎tick全Rawをスナップショット」はコスト大。評価器が個別に `get` すると読取中更新でちぐはぐの恐れ。
- **直し方**: 既定は**評価器が必要値だけを短いcriticalで読む**。複数値の原子整合が要る状態のみ、その評価器内で
  `critical_enter/exit` で囲って一括読みする（全体スナップショットは任意・既定オフ）。スレッドモデルを明記。
- **反映**: basic-design §5.2、detailed-design §6.4 を修正（全体スナップショット必須をやめ、局所整合に）。→ 反映済。

### F4【Minor / C3】内部表現と外部表現（pf_value_t）の差が未説明
- **問題**: BLOB は内部で固定プールに `{offset,size}` で持つが、`pf_value_t.blob.ptr` はプール内を指す外部ビュー。寿命・並行性の注意が必要。
- **直し方**: 「`pf_data_get` はコピー（安全）、`pf_data_get_value` の blob はゼロコピー参照（criticalまたは単一文脈でのみ有効）」と明記。
- **反映**: detailed-design §3.5/§3.3 に注記。→ 反映済。

### F5【Minor / C2】過剰設計（YAGNI）の懸念
- **問題**: FSM・デバウンス・BLOBプールは要件由来だが、単純機種には過剰に見える可能性。
- **直し方**: **未使用時ゼロコスト**を明記（`fsm_count=0`/`debounce_n=0`/`PF_RAW_POOL_BYTES=0` で機能無効・RAM消費なし）。
- **反映**: basic-design §6.5・detailed-design §6.2 に注記。→ 反映済。

### F6【Minor / C1・C3】予約ID（PF_STATE_ANY=0xFFFF）の扱い
- **問題**: 0xFFFF を「全状態購読」の番兵に使うが、有効ID空間との衝突注意が必要。
- **直し方**: **0xFFFF は予約**（有効な data/state ID として使用禁止）と明記し、init検証で弾く。
- **反映**: detailed-design §7.2 に注記。→ 反映済。

### F7【Nit / C4】テスト雛形は空にせず最小の実アサーションを置く
- **問題**: 空のテスト雛形は C4 で減点（assert無し）。
- **直し方**: `tests/` に Unity 風の**実アサーション付き**の最小テスト（型不一致→TYPE_MISMATCH 等）を同梱。
- **反映**: スケルトン生成（E）で対応。→ 実装フェーズで反映。

## 6. 追補: C++実装への移行（2026-07-02）

オーナー指示により、実装言語を C（C99/C11）から **組込み向けイディオマティックC++（C++17）** へ移行した。
公開API・C ABI互換（`extern "C"`）・全静的確保／リアルタイム制約は変更しない前提での移行。

### 6.1 変更内容（要約）
- `src/*.c` → `*.cpp`。各レイヤを匿名namespace内クラス（`data_dictionary` / `state_registry` /
  `monitor_engine` / `observer_dispatcher` / `core_context`）としてカプセル化し、モジュールごとに
  単一インスタンス（シングルトン・静的記憶域）を保持。公開 `extern "C"` 関数は1行で委譲するだけの
  薄いラッパーとした（詳細は detailed-design.md §0.2）。
- `port/*.c`・`models/model_sample/*.c`・`examples/app_demo.c`・`tests/test_printer_fw.c` も `.cpp` へ。
- `CMakeLists.txt`/`Makefile` を C++17・`g++`/`-fno-exceptions -fno-rtti` に更新。

### 6.2 自己レビュー（本移行に対して）
| 観点 | 評価 | コメント |
|------|:---:|---------|
| 責務分離・カプセル化 | ◎ | クラス化により private メンバでの隠蔽が明確化。C版より境界が強固 |
| C ABI互換の維持 | ◎ | 公開ヘッダ・関数シグネチャは無変更。gccでのCリンク（`-lstdc++`要）も想定しREADMEに明記 |
| 組込み制約の維持 | ◎ | `-fno-exceptions -fno-rtti` をビルドで強制。コンストラクタは失敗しない設計（`init()`で明示） |
| 過剰設計の回避 | ○ | 仮想関数・テンプレート・STLコンテナは意図的に不使用。関数ポインタ注入方式を維持しC版からの逸脱を最小化 |
| リスク | △ | C++実装のため、Cから利用する際は `libstdc++` のリンクが必要になる点は非対称性として残る（README・detailed-designに明記済み） |
