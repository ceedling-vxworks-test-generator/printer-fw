# RIM_AdapterLayer 詳細設計書 (RIM_new)

クラス図は `03_クラス図.md`、シーケンス図は `04_シーケンス図.md` を参照。

## 1. コンポーネント

| コンポーネント | 所属 | 役割 |
|----------------|------|------|
| `RawDataInput` | framework | 受理点。型自由な Push 群を提供し、Rule選択→変換→性質判別→post を実行 |
| `RawValue` | framework | 受理点の型自由な生値(スカラ / 構造体・配列のバイト列参照) |
| `IRule` | framework | `Convert(RawValue, Context) → optional<RIMValue>`。正規化規則の抽象 |
| `IRuleResolver` | framework | `SelectRule(id) → const IRule*`。id→Rule 解決の抽象(devices実装) |
| `IInputClassifier` | framework | `Classify(id) → optional<InputKind>`。id→性質 の抽象(devices実装) |
| `ICentralInputPort` | framework(L2提供) | `PostFaultInput/PostOperationReport/PostCurrentValueInput`。送出先の抽象 |
| 具象 Rule 群 | devices | `CelsiusRule` / `PercentRule` / … 実際の正規化 |
| `PrinterADataProfile` | devices | `IRuleResolver` + `IInputClassifier` 実装。Rule実体を所有 |

## 2. データ型

### 2.1 RawValue(IN)
```cpp
struct RawValue {
    enum class Kind { kScalar, kBytes };
    Kind        kind;
    double      scalar;   // kScalar
    const void* data;     // kBytes: 構造体/配列の先頭(非所有)
    size_t      size;     // kBytes: 総バイト長
    size_t      count;    // kBytes: 要素数(配列=n, 構造体=1)
    static RawValue Scalar(double);
    template<class T> static RawValue Struct(const T&);       // data=&s, count=1
    template<class T> static RawValue Array(const T*, size_t);// data=a, count=n
    template<class T> const T* As() const;                    // 先頭を T* として解釈
    template<class T> const T& ElementAt(size_t i) const;     // 配列要素
};
```

### 2.2 RIMDataItem(OUT)
```cpp
struct RIMDataItem { RIMDataId id; RIMValue value; DataContext context; };
```

## 3. in → out の経路(処理フロー)

`RawDataInput::Intake(id, RawValue, ctx)` が中核。

```
Push*(id, raw, ctx)                       // スカラ/構造体/配列を RawValue 化
  1. resolver.SelectRule(id)              // Rule 未定義 → kErrConvert
  2. item.id = id; item.context = *ctx
  3. rule.Convert(RawValue, ctx)          // 正規化。失敗 → kErrConvert
     → item.value = RIMValue
  4. classifier.Classify(id)              // 性質不明 → kErrClassify
  5. switch(kind):
       kFault           → port.PostFaultInput(item)
       kOperationReport → port.PostOperationReport(item)
       kCurrentValue    → port.PostCurrentValueInput(item)
```

- スカラ(`PushI32/F/U32`)は `RawValue::Scalar(double)`。
- 構造体(`PushStruct<T>`)は `RawValue::Struct(s)`(バイト列参照、count=1)。
- 配列(`PushArray<T>`)は `RawValue::Array(a, n)`(バイト列参照、count=n)。
- **RawValue は Push 呼び出し中のみ有効**(呼び出し側が実体を所有)。`Convert` は同期的に
  `RIMValue`(値コピー) を生成するため、post までに参照は解決済み。

## 4. 新規ルールを追加する流れ

外部から新しいデータ種別(または新しい入力形式)を受けたいとき:

1. **id を用意**: `framework/inc/datastore/RIMDataId.hpp` に列挙子を追加(`kCount` の手前)。
   ※ 既存 id を別形式で受けたいだけなら不要。
2. **Rule を実装**: `IRule` を実装するクラスを devices 側に追加。
   `Convert(RawValue, ctx)` で RawValue(スカラ/構造体/配列) を `RIMValue` へ正規化する。
   ```cpp
   class MyRule final : public IRule {
     std::optional<RIMValue> Convert(const RawValue& raw, const DataContext& ctx) const override {
       // 構造体例: auto* p = raw.As<MyPacket>(); return RIMValue::Percent(p->level);
       // 配列例  : sum over raw.ElementAt<uint8_t>(i) ... return RIMValue::Percent(avg);
     }
   };
   ```
3. **Resolver に登録**: `PrinterADataProfile::SelectRule(id)` に `id → &myRule_` の分岐を追加し、
   Rule 実体をメンバとして所有させる。
4. **性質を登録**: `PrinterADataProfile::Classify(id)` に `id → InputKind` を追加。
5. **受理**: 呼び出し側は `PushStruct/PushArray/PushF` 等でそのまま投入できる(Adapter変更不要)。
6. **テスト**: `IRule` 単体 + `RawDataInput`(モック port) で検証(§6)。

> 変更は「id 追加 + Rule 追加 + Resolver/Classifier への2行追記」に局所化される。
> framework(共通機構)には触れない。

## 5. DataStore で新しいデータを管理する流れ

Adapter が送出した `RIMValue` を L2 でどう保持・提供するか。**性質(kind)により経路が異なる**。

### 5.1 最新値系(CurrentValue) — 最も一般的
1. `Classify(id) = kCurrentValue`。`CentralInputPort.PostCurrentValueInput` → `CurrentValueBuffer`。
2. `CurrentValueRegistry::Apply(item)` が `DomainForId(id)` で**副ドメイン**を判定して格納。
   → 新 id を既存副ドメイン(Environment/Consumable/Safety/Maintenance/Health)に割り当てるなら
   `DomainForId` に分岐を追加するだけ。
3. `MakeSnapshot(domains)` の該当副Snapshot(例 `EnvironmentSnapshot`)にフィールドを追加して露出。
4. Capability 側(`ICapabilityBuilder`)がそのフィールドを参照して判定する。

### 5.2 異常系(Fault) / 動作報告系(OperationReport)
- Fault: `PostFaultInput` → `FaultInputQueue` → `FaultDispatcher` → `FaultRegistry`(FixedMap で add/remove/update)。
- Operation: `PostOperationReport` → `OperationReportQueue` → `OperationDispatcher` → `OperationRegistry`。

### 5.3 新しい**副ドメイン**や**新しい Registry** が必要な場合
- 新副ドメイン: `RegistryDomain.hpp` にビットを追加 → `CurrentValueRegistry.DomainForId` と
  `MakeSnapshot` に対応 → `Snapshot.hpp` に副Snapshot 追加 → `MachineRegistry.Capture` の
  `kDomainCurrentAll` に含める。
- 構造化値をそのまま保持したい場合: `ValueType` に新種別を追加し、`RIMValue` に対応する
  格納表現(例: 固定長バッファ)を足す。ただし Adapter の原則は「正規化して単純値で渡す」ため、
  まずは既存の `RIMValue` 種別へ落とせないかを検討する。

> 責務境界: Adapter は「正規化して post するだけ」。**どのドメインに保持し、どう Snapshot 化するかは
> L2 の責務**。Adapter 側の変更(§4)と L2 側の変更(§5)は独立して行える。

## 6. Adapter 単体テスト方針

Adapter は `ICentralInputPort` にのみ依存するため、**L2 を組まずに単体検証**できる。

- **モック port**: `ICentralInputPort` を実装し、post された `RIMDataItem` を性質別に記録する
  `MockPort` を用意する。
- **テスト用 Rule/Resolver**: scalar / array / struct の Rule と、それらを id へ割り当てる
  `IRuleResolver + IInputClassifier` をテスト内に定義する。
- **検証観点**:
  - スカラ/構造体/配列 各 Push が正しい `RIMValue` へ正規化されること。
  - 性質に応じて正しい post(Fault/Operation/CurrentValue)へ振り分くこと。
  - Rule 未定義 id → `kErrConvert`、性質不明 → `kErrClassify`、型不一致(scalar用へ構造体) → `kErrConvert`。

実装は `test/unit/AdapterTest.cpp` を参照(MockPort + TestProfile + scalar/array/struct Rule)。

## 7. エラー処理(RIMResult)

| 結果 | 契機 |
|------|------|
| `kOk` | 正常に post された |
| `kErrConvert` | Rule 未定義、または Convert が nullopt(型不一致・変換不能) |
| `kErrClassify` | Classify が性質を返せない |
| `kErrKindMismatch` | (L2側)post種別と id 分類/値型の不一致 |
| `kErrPost` | (L2側)Queue 満杯=喪失 |
| `kErrInvalidArg` | id 範囲外等 |
