# RIManager 製品要求定義書仕様

## 1. 目的

本資料は RIManager における製品要求定義書の仕様を定義する。

製品要求定義書は Excel 形式で管理し、製品要求者と製品実装者のインターフェースとして利用する。

本資料で定義された情報をもとに、製品実装者は products 配下の製品実装を作成する。

---

## 2. 責務

### 製品要求者

以下を定義する。

- Domain
- Data
- Capability

### 製品実装者

以下を実装する。

- Data正規化処理
- Capability生成処理
- Adapter実装
- Product実装

### RIManager

以下の機能を提供する。

- Storage
- Snapshot
- Capability実行基盤
- Publisher
- C API

---

## 3. ファイル形式

Excel形式とする。

```text
ProductRequirement.xlsx
```

---

## 4. シート構成

要求定義書は以下の3シートで構成する。

```text
Domain
Data
Capability
```

---

## 5. Domainシート

### 目的

製品で使用する論理Domainを定義する。

### カラム

```text
DomainId
DomainName
Description
```

### 記載例

```text
DomainId      : 1
DomainName    : Machine
Description   : 機械状態
```

```text
DomainId      : 2
DomainName    : Job
Description   : 印刷ジョブ状態
```

```text
DomainId      : 3
DomainName    : Consumable
Description   : 消耗品状態
```

### 制約

- DomainIdは製品内で一意
- DomainNameは製品内で一意
- 削除済みIDの再利用は禁止

---

## 6. Dataシート

### 目的

製品で扱うDataを定義する。

### カラム

```text
DataId
DataName
ValueType
Domain
Normalization
Description
```

### 項目説明

#### DataId

データ識別子。

```text
製品内で一意
```

---

#### DataName

データ名称。

例：

```text
Temperature
DoorOpen
EngineReady
```

---

#### ValueType

値型。

利用可能な型：

```text
Bool
Int32
Double
Binary
```

---

#### Domain

所属Domain。

Domainシートで定義されたDomainNameを指定する。

---

#### Normalization

正規化仕様。

コードではなく説明文で記載する。

例：

```text
0をfalse、1をtrueとして扱う
```

```text
受信値を10で除算する
```

```text
255は異常値として扱う
```

---

#### Description

データ説明。

例：

```text
内部温度
ドア開閉状態
トナー残量
```

### 記載例

```text
DataId         : 1001
DataName       : Temperature
ValueType      : Double
Domain         : Machine
Normalization  : 受信値を10で除算する
Description    : 内部温度
```

```text
DataId         : 1002
DataName       : DoorOpen
ValueType      : Bool
Domain         : Machine
Normalization  : 0をfalse、1をtrueとして扱う
Description    : ドア開閉状態
```

### 制約

- DataIdは製品内で一意
- DataNameは製品内で一意
- DomainはDomainシートの定義を参照する

---

## 7. Capabilityシート

### 目的

Capability仕様を定義する。

### カラム

```text
CapabilityId
CapabilityName
ValueType
InputData
GenerationRule
Description
```

### 項目説明

#### CapabilityId

Capability識別子。

```text
製品内で一意
```

---

#### CapabilityName

Capability名称。

例：

```text
PrintReady
LowToner
CanPrint
```

---

#### ValueType

Capabilityが返却する型。

利用可能な型：

```text
Bool
Int32
Double
Binary
```

---

#### InputData

Capability生成に利用するData。

複数ある場合はカンマ区切りで記載する。

例：

```text
DoorOpen,TonerRemain,EngineReady
```

---

#### GenerationRule

Capability生成仕様。

コードではなく説明文で記載する。

例：

```text
全入力が正常の場合true
```

```text
入力値が10未満の場合true
```

```text
入力値の平均値を返却する
```

---

#### Description

Capability説明。

例：

```text
印刷可能状態
トナー不足状態
給紙可能状態
```

### 記載例

```text
CapabilityId    : 2001
CapabilityName  : PrintReady
ValueType       : Bool
InputData       : DoorOpen,TonerRemain,EngineReady
GenerationRule  : 全入力が正常の場合true
Description     : 印刷可能状態
```

```text
CapabilityId    : 2002
CapabilityName  : LowToner
ValueType       : Bool
InputData       : TonerRemain
GenerationRule  : 残量10%未満の場合true
Description     : トナー不足状態
```

### 制約

- CapabilityIdは製品内で一意
- CapabilityNameは製品内で一意
- InputDataはDataシートで定義されたDataを参照する

## 9. 管理方針

### ID管理

削除済みIDの再利用は禁止する。

理由：

```text
後方互換性維持
ログ解析の容易化
保守性向上
```

### 命名規則

DomainName

```text
PascalCase
```

DataName

```text
PascalCase
```

CapabilityName

```text
PascalCase
```

例：

```text
Machine
DoorOpen
TonerRemain
PrintReady
```

## 11. 最終目標

要求定義書を製品仕様の唯一の入力情報とする。

```text
製品要求者
    ↓
製品要求定義書(Excel)
    ↓
製品実装者
    ↓
products/printer_x
    ↓
RIManager統合
```

新製品追加時には、要求定義書を作成することで実装が開始できる状態を目指す。
