# RIManager Architecture vNext

## 目的

RIManager を以下の方針で再構築する。

## 方針

- Core は処理基盤のみを持つ
- Core は製品知識を持たない
- Product が定義を持つ
- Product が Core を利用する
- Error を特別扱いしない
- Domain を中心にデータを集約する
- DataItem と Capability の両方を通知対象とする
- Snapshot により Domain 単位の整合性を保証する
- C API は公開インターフェースとして提供する

# DataItem

## 概要

DataItem はデータ定義。

実データではない。

Product が定義する。

---

## DataItem

```cpp
struct DataItem
{
    DataItemId id;

    std::string_view name;

    ValueType valueType;

    std::string_view domain;

    Context context;

    IAdapterRule* adapterRule;

    IDiffRule* diffRule;
};
```

---

## DataItemの責務

定義のみ。

```text
保持しない
通知しない
生成しない
```

---

## domain

所属Domain。

例

```text
Temperature → Environment

Humidity → Environment

JobActive → Job
```

---

## adapterRule

正規化処理。

例

```text
Kelvin → Celsius

RawCode → Enum
```

---

## diffRule

差分判定規則。

例

```text
完全一致

誤差許容比較
```

---

---

## requiredDataItems

例

```text

```

# 設計原則

- Coreは処理基盤のみ
- Productは定義を持つ
- ProductがCoreを利用する
- Errorを特別扱いしない
- DataItemはDomainに所属する
- Domainは通知集約単位
- Capabilityは必要DataItemを宣言する
- PipelineはDomain変更をCapability生成へ変換する
- SnapshotはDomain単位で整合性を保証する
- Store→CapabilityはDataItem変更通知
- Capability→PublisherはCapability変更通知
- Storeは1つのQueueを持つ
- CapabilityはPipelineごとのQueueを持つ
- Publisherは1つのQueueを持つ
- CoreはProductを参照してはならない
