# Adapterレイヤ 外部仕様書

対象: `core/adapter`(`AdapterDispatcher` / `IHardwareAdapter` / `MockAdapter`)

本書は、Adapterレイヤを**利用する側**(`products/common/rim_api.cpp`、ハードウェア入力を扱う実装等)向けに、
公開インターフェースの入出力・前提条件・エラー条件をまとめたものである。内部実装(正規化アルゴリズムやStoreへの
受け渡し方法など)は `02_内部仕様書.md` / `03_詳細設計書.md` を参照。

---

## 1. 概要

Adapterレイヤは、**「RIDataIdごとに正しい型で用意された値」を受け取り、DataItemDefinitionの正規化規則(normalize)に
従って正規化した上でStoreレイヤ(`StoreInputQueue`)へ引き渡す**、唯一の受付窓口である。

製品固有の知識(どのRIDataIdが何を意味するか等)は一切持たず、`ProductDefinition`経由でのみDataItemの型・
正規化規則を参照する(`docs/internal/architecture.md`の設計方針に準拠)。

## 3. `AdapterDispatcher`

### 3.1 コンストラクタ

```cpp
AdapterDispatcher(
    const ProductDefinition& product,
    StoreInputQueue& queue);
```

| 引数 | 説明 |
| --- | --- |
| `product` | このAdapterが対象とする製品定義。生存期間はAdapterDispatcherより長いこと(参照保持)。 |
| `queue` | 正規化後の値の投入先となるStoreレイヤの入力キュー。生存期間はAdapterDispatcherより長いこと(参照保持)。 |

### 3.2 `Dispatch()`

```cpp
bool Dispatch(
    RIDataId id,
    const RIMValue& value);
```

外部から見た**入出力契約**は以下の通り。

| 項目 | 内容 |
| --- | --- |
| 入力 `id` | 値を設定したいデータ項目のRIDataId。 |
| 入力 `value` | `id`に対応する`DataItemDefinition::rawValueType`と**同じ型**でタグ付けされた`RIMValue`であること(呼び出し側の責務)。 |
| 戻り値 `true` | 正規化・Storeレイヤへの投入に成功。 |
| 戻り値 `false` | 以下のいずれかにより処理を行わなかった。①`id`が製品定義に存在しない、②`value`の型が`rawValueType`と一致しない。 |
| 副作用 | 成功時、正規化後の値が`StoreInputQueue`へ1件Pushされる。失敗時は副作用なし。 |
| スレッド安全性 | `Dispatch()`自体は状態を持たないため呼び出し側スレッドで同期的に実行できる。内部で使う`StoreInputQueue::Push()`はミューテックスで保護されているため、複数スレッドから同時に呼び出してよい。 |

**呼び出し側が必ず守ること**:
`value`の型(`RIMValue::type`)を、呼び出し前に`id`に対応する`rawValueType`へ合わせること。合っていない場合、
`Dispatch()`は何もせず`false`を返す(型不一致のまま処理が進むことはない)。

**利用例**(`products/common/rim_api.cpp`の`RIM_SetBool`):

```cpp
const rim::RIMValue rawValue =
    rim::RIMValueFactory::CreateBool(value != 0);

return g_context->dispatcher.Dispatch(dataId, rawValue)
       ? RI_SUCCESS
       : RI_INVALID_PARAMETER;
```

## 4. `IHardwareAdapter`

ハードウェア起点(実機/エミュレータ等、生の数値しか持たない入力源)のAdapter実装が満たすべきインターフェース。

```cpp
class IHardwareAdapter
{
public:
    virtual bool Initialize() = 0;
    virtual bool Poll() = 0;
    virtual void Shutdown() = 0;
};
```

| メソッド | 契約 |
| --- | --- |
| `Initialize()` | `Poll()`より前に一度だけ呼ばれる想定。失敗時は`false`。 |
| `Poll()` | 1回分のハードウェア読み取り〜`AdapterDispatcher::Dispatch()`への引き渡しまでを行う。呼び出し周期は呼び出し元(スケジューラ)が管理する。読み取り失敗、または`Dispatch()`拒否時は`false`。 |
| `Shutdown()` | 終了処理。 |

現時点でこのインターフェースを実装する具体的なハードウェア用クラスはリポジトリ内に存在しない
(旧`PrinterAdapter`はテスト専用の固定値スタブだったため、`Dispatch()`のシグネチャ変更に伴い削除済み)。

---

## 5. `MockAdapter`

`IHardwareAdapter`の何もしない実装(テストダブル)。`Initialize()`/`Poll()`は常に`true`を返すのみで、
Storeへは一切値を投入しない。実ハードウェア実装が無い環境でも「アダプタが存在する」前提のコードパスを
通しておきたい場合に使う。

---

## 6. 非対象(このレイヤが行わないこと)

- 型変換以外の値の妥当性検証(範囲チェック等)は行わない。それは`normalize`/`store`側の責務。
- Capability評価・通知は行わない(Storeレイヤ以降の責務)。
- 複数の値をまとめて処理するバッチ処理は提供しない(1回の`Dispatch()`呼び出しにつき1データ項目)。
- スレッド/ワーカーの管理は持たない(`Dispatch()`は同期呼び出し)。
