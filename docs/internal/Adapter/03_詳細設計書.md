## 2. `AdapterDispatcher`

### 2.1 メンバ変数

| 名前 | 型 | 説明 |
| --- | --- | --- |
| `product_` | `const ProductDefinition&` | 対象製品定義への参照。コンストラクタで束縛、以降不変。 |
| `queue_` | `StoreInputQueue&` | 正規化後の値の投入先。コンストラクタで束縛、以降不変。 |

### 2.2 メソッド

#### コンストラクタ

```cpp
AdapterDispatcher(
    const ProductDefinition& product,
    StoreInputQueue& queue);
```

`product_`/`queue_`を初期化子リストで束縛するのみ。処理なし。

#### `bool Dispatch(RIDataId id, const RIMValue& value)`

実装: `core/adapter/src/AdapterDispatcher.cpp:10-59`

| Step | 処理 | 対応コード |
| --- | --- | --- |
| 1 | `FindDataItem(product_, id)`で`DataItemDefinition`を検索 | L15-18 |
| 2 | `definition == nullptr`なら`false`を返却 | L20-24 |
| 3 | `value.type != definition->rawValueType`なら`false`を返却 | L26-33 |
| 4 | `definition->normalize(value, nullptr)`を呼び出し`setValue`を得る | L35-40 |
| 5 | `RIMDataItem item`を構築(`id`/`setValueType`/`setValue`) | L42-51 |
| 6 | `queue_.Push(item)` | L53-56 |
| 7 | `true`を返却 | L58 |

**計算量**: `FindDataItem`は`ProductDefinition::dataItems`(配列)への線形探索
(`products/common/ProductDefinition.hpp`実装依存。要素数はDataItem定義数)。それ以外は定数時間。

**副作用**: Step6でのみ発生(`StoreInputQueue`への1件Push)。Step2/3で中断した場合は副作用なし。

## 3. `IHardwareAdapter`

純粋仮想インターフェース。実装クラスは`AdapterDispatcher`への参照を持ち、`Poll()`内で
`Dispatch()`を呼び出す構成を想定する(具体実装は現状リポジトリに存在しない。旧`PrinterAdapter`は
`Dispatch()`のシグネチャ変更に伴い削除済み)。

| メソッド | シグネチャ | 実装義務 |
| --- | --- | --- |
| `Initialize` | `virtual bool Initialize() = 0;` | あり(純粋仮想) |
| `Poll` | `virtual bool Poll() = 0;` | あり(純粋仮想) |
| `Shutdown` | `virtual void Shutdown() = 0;` | あり(純粋仮想) |
| デストラクタ | `virtual ~IHardwareAdapter() = default;` | 仮想デストラクタ(ポリモーフィックな削除に対応) |

**将来、ハードウェア実装を追加する場合の設計指針**:

```cpp
class SomeHardwareAdapter : public IHardwareAdapter
{
public:
    explicit SomeHardwareAdapter(AdapterDispatcher& dispatcher);

    bool Poll() override
    {
        // 1. ハードウェアから生値を読む(型はハードウェア依存)
        // 2. 対象RIDataIdのrawValueTypeに合わせてRIMValueFactory::CreateXxxで型付け
        //    (rawValueTypeはFindDataItem(product, id)->rawValueTypeで取得できる)
        // 3. dispatcher_.Dispatch(id, typedValue) を呼ぶ
    }

private:
    AdapterDispatcher& dispatcher_;
};
```

ハードウェア側の生値→`RIMValue`への型付けロジックは、**`Dispatch()`側ではなく各Adapter実装側**に置く
(`02_内部仕様書.md` 5章、既知の制約を参照)。

## 5. 使用する共通データ型(再掲)

### `RIMDataItem` (`core/common/include/RIMDataItem.hpp`)

```cpp
struct RIMDataItem
{
    RIDataId id;
    ValueType valueType;
    RIMValue value;
};
```

### `DataItemDefinition`(抜粋、`core/common/include/DataItemDefinition.hpp`)

```cpp
struct DataItemDefinition
{
    RIDataId id;
    std::string_view name;
    std::string_view domain;
    std::string_view route;

    ValueType rawValueType;    // Dispatch()の入力valueが持つべき型
    ValueType setValueType;    // normalize()の出力が持つべき型
    ValueType storeValueType;  // storeレイヤでの永続化時の型(Adapterレイヤでは未使用)
    ValueType getValueType;    // 現状どこからも参照されていない(未配線)

    NormalizeCallback normalize;
    StoreCallback store;       // Adapterレイヤでは未使用(Storeレイヤで使用)
    DiffCallback diff;         // Adapterレイヤでは未使用
};
```

### `StoreInputQueue::Push()` (`core/store/include/StoreInputQueue.hpp`)

```cpp
void Push(const RIMDataItem& item);
```

`std::mutex`でガードされたスレッドセーフなキュー。`Dispatch()`はこの`Push()`を呼ぶのみで、
Pop側(`DataStoreWorker`)の制御は行わない。

## 6. テスト観点(実装時のチェックリスト)

| # | 観点 | 期待結果 |
| --- | --- | --- |
| 1 | 登録済み`id`・型一致の`value`を渡す | `true`、キューに1件Push |
| 2 | 未登録`id`を渡す | `false`、キューへの投入なし |
| 3 | `id`は登録済みだが`value.type`が`rawValueType`と不一致 | `false`、キューへの投入なし |
| 4 | `rawValueType == setValueType`のDataItem(現行全項目) | `item.valueType`が`setValueType`と一致し、`RIMValue::type`も同じ型 |
| 5 | `normalize`が単位変換等を行うDataItem(例: 温度) | 変換後の値がキューに積まれる |
