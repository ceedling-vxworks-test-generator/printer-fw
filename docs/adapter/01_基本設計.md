# RIM_AdapterLayer 基本設計書 (RIM_new)

## 1. 概要

RIM_AdapterLayer(L1) は、外部コンポーネントから入力されるデータをシステム内部で利用可能な
統一表現へ**正規化**し、RIM_DatastoreLayer(L2) へ受け渡す層である。
外部仕様と内部仕様の境界として機能し、後続層から外部仕様の差異を隠蔽する。

本書は `RIM_new`(C++実装) の Adapter レイヤの基本設計を、`old/ex/` の
`AdapterLayer仕様設計書.md`(仕様③) に準拠して記す。

## 2. 責務 / 非責務

| | 内容 |
|---|---|
| **責務** | 外部入力の受理 / 正規化処理(Rule)の選択 / データ正規化 / L2 への送出(`Post`) |
| **非責務** | **入力性質の判別(Fault/OperationReport/CurrentValue)とレーン振り分け** / 意味解釈・状態判定・ビジネスロジック・閾値判定・データ保持・状態管理(これらは L2/L3 の責務) |

## 3. 位置づけ

```
入力元 → [RIM_AdapterLayer] → CentralInputPort(L2) → 3レーン → …
```

Adapter は L2 が提供する **`ICentralInputPort`** にのみ依存する(具象 DataStore に非依存)。
これにより Adapter は単体でテスト可能(モック port を差し込む)。

## 4. in / out 情報

### 4.1 IN(受理する情報)

受理点 `RawDataInput` が外部へ提供する受理APIは **`Push(id, RawValue, ctx?)` の1つのみ**。
型自由さは `RawValue`(タグ付き生値)側が吸収し、呼出側は用途に応じたファクトリで組み立てて渡す。

| 呼出側の組み立て | RawValue の種別 | 用途 |
|------------------|----------------|------|
| `RawValue::Scalar(double)` | スカラ | 整数/実数センサ・コード/カウンタ等(int32/uint32はdoubleへ暗黙変換) |
| `RawValue::Struct(const T&)` | **構造体**(バイト列参照) | 複合パケット等 |
| `RawValue::Array(const T*, n)` | **配列**(バイト列参照) | 多セル/多チャンネル等 |

呼び出し例: `adapter.Push(id, RawValue::Scalar(25.0), ctx)` / `adapter.Push(id, RawValue::Struct(pkt))`。

- **id**: `RIMDataId`(論理識別子)。加工せず素通しする。現行は11種:
  Temperature / Humidity / Pressure / InkLevel / WiperLevel / CoverOpen / EStop /
  JobProgress / FaultCode / MaintenanceCount / UnitAlive。
- **RawValue**: 受理点の型自由さを吸収する型消去済みの生値。
  スカラ(double 集約)か、構造体・配列(先頭ポインタ + サイズ + 要素数の**非所有参照**)を保持する。
- **Context**(`DataContext`, 任意): 正規化補助。`unit` / `scaleX1000` / `faultState` / `key`。
  - `unit`(`SourceUnit`): **生値がどの単位で来たか**。同じ id へ異なる単位で値が届く場合に、
    id を増やさず Rule 側で分岐するための情報。未指定は `kNormalized`(既に正規化済み=換算しない)。
    例) 温度は摂氏(`kCelsius`)でも華氏(`kFahrenheit`)でも同じ `kTemperature` へ投入でき、
    DataStore へは常に絶対温度(ケルビン)で格納される。

### 4.2 OUT(送出する情報)

`ICentralInputPort` の **`Post(item)`** へ **`RIMDataItem { id, value, context }`** を送出する。
送出点は1つで、Adapter は性質判別を行わない。

| 送出先 | 内容 |
|--------|------|
| `Post(RIMDataItem)` | 正規化済みの1件を渡す。**性質判別(Fault/OperationReport/CurrentValue)と<br/>レーン振り分けは L2(`CentralInputPort`)が行う** |

> **責務分離の理由**: 「どのレーンに入るか」は保持先の知識であり L2 の関心事。
> 以前は Adapter が `Classify` して3種postを選び、L2 が同じ `Classify` で再検証する
> **二重分類**になっていた。Adapter は正規化のみに責務を絞り、`IInputClassifier` への
> 依存も L2 側だけが持つ。

- **value**: `RIMValue`(正規化後の内部統一表現。タグ付きunion)。
  型: KelvinX100 / Percent / JobProgress / FaultCode / Bool / UInt32。
  温度は入力単位に関わらず**絶対温度(ケルビン)×100**へ正規化済み。
- **戻り値**: `RIMResult`(kOk / kErrConvert / kErrClassify / kErrKindMismatch / kErrPost / kErrInvalidArg)。

> **正規化の原則**: 外部形式(構造体・配列といった**型**の差、および摂氏/華氏といった**単位**の差)は
> Adapter で内部統一表現(`RIMValue`)へ**正規化**して送出する。後続層は `RIMValue` のみを扱い、
> 外部フォーマットも単位も意識しない(温度なら常にケルビンとして読める)。
> (構造化データを L2 でそのまま保持したい場合の流れは `02_詳細設計.md` §5 を参照)

## 5. 設計方針

- **Push方式**: 入力発生時に即時処理(ポーリングしない)。
- **Rule方式**: 正規化は id ごとの Rule に集約。新データ種別追加は Rule 追加で対応(変更影響を局所化)。
- **型自由の吸収**: スカラは double へ集約、構造体/配列は `RawValue` のバイト列参照で受理。
  Rule が同期的に `RIMValue` へ正規化するため、参照の生存期間内で完結する。
- **疎結合**: Adapter → L2 は `ICentralInputPort` 抽象経由。単体テスト・機種差し替えが容易。

## 6. 機種可変 / 共通の分離

| 区分 | 要素 |
|------|------|
| framework(共通) | `RawDataInput` / `RawValue` / `IRule` / `IRuleResolver` / `IInputClassifier` / `ICentralInputPort` |
| devices(機種可変) | `RIMDataId`(id一覧) / 具象 Rule 群 / `PrinterADataProfile`(SelectRule + Classify) |

> `RIMDataId` は id の**中身**(何種類あるか・名前)を持つため devices 側で定義する。
> framework は `"datastore/RIMDataId.hpp"` という**型名**にのみ依存し、機種ごとの実体は
> インクルードパス解決(devices側が提供)で差し替わる。詳細は `02_詳細設計.md` §1.1。
