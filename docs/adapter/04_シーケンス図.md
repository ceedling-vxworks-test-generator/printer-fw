# RIM_AdapterLayer シーケンス図 (RIM_new)

## 1. in → out の経路(スカラ)

```mermaid
sequenceDiagram
    participant Ext as 入力元
    participant RDI as RawDataInput
    participant RR as IRuleResolver
    participant Rule as IRule
    participant IC as IInputClassifier
    participant Port as ICentralInputPort

    Ext->>RDI: Push(id, RawValue::Scalar(25.0), ctx)
    RDI->>RR: SelectRule(id)
    RR-->>RDI: IRule*
    RDI->>Rule: Convert(RawValue, ctx)
    Rule-->>RDI: RIMValue(正規化)
    RDI->>IC: Classify(id)
    IC-->>RDI: InputKind
    alt kCurrentValue
        RDI->>Port: PostCurrentValueInput(item)
    else kFault
        RDI->>Port: PostFaultInput(item)
    else kOperationReport
        RDI->>Port: PostOperationReport(item)
    end
    Port-->>RDI: RIMResult
    RDI-->>Ext: RIMResult
```

## 2. in → out の経路(配列)

```mermaid
sequenceDiagram
    participant Ext as 入力元
    participant RDI as RawDataInput
    participant Rule as ArrayRule(IRule)
    participant Port as ICentralInputPort

    Ext->>RDI: Push(id, RawValue::Array(uint8[3]{40,50,60}, 3), ctx)
    RDI->>Rule: Convert(RawValue, ctx)
    Note over Rule: raw.ElementAt<uint8>(i) を走査<br/>平均=50 → Percent(50)
    Rule-->>RDI: RIMValue::Percent(50)
    RDI->>Port: PostCurrentValueInput(item)
    Port-->>RDI: kOk
```

## 3. in → out の経路(構造体)

```mermaid
sequenceDiagram
    participant Ext as 入力元
    participant RDI as RawDataInput
    participant Rule as StructRule(IRule)
    participant Port as ICentralInputPort

    Ext->>RDI: Push(id, RawValue::Struct(SamplePacket{level:77}), ctx)
    RDI->>Rule: Convert(RawValue, ctx)
    Note over Rule: raw.As<SamplePacket>()->level<br/>→ Percent(77)
    Rule-->>RDI: RIMValue::Percent(77)
    RDI->>Port: PostCurrentValueInput(item)
    Port-->>RDI: kOk
```

> RawValue はバイト列を**参照**するだけ(コピーしない)。Rule が同期的に `RIMValue`(値)へ
> 正規化するため、Push 呼び出しから抜ける前に参照は解決される(ダングリングしない)。

## 4. 新規ルールを追加する流れ(開発手順)

```mermaid
flowchart TD
    A["新データ種別/新入力形式が必要"] --> B{"新しい id が要る?"}
    B -- はい --> C["devices/printer_a/inc/datastore/RIMDataId.hpp に列挙子追加<br/>(machine-agnosticなframeworkは無改修)"]
    B -- いいえ --> D
    C --> D["IRule 実装クラスを devices に追加<br/>Convert(RawValue)→RIMValue"]
    D --> E["PrinterADataProfile.cpp: 単一インスタンスを追加<br/>const MyRule kMyRule;"]
    E --> F["同ファイルの kTable に1行追加<br/>{ id, &kMyRule, InputKind }"]
    F --> G["呼び出し側は Push(id, RawValue::Struct/Array/Scalar(...)) で投入(Adapter変更不要)"]
    G --> H["IRule単体 + RawDataInput(モックport) + PrinterADataProfileTest で単体テスト"]
```

- 変更は **id追加 + Rule追加 + `kTable` 1行追記** に局所化(旧: SelectRule/Classify 2箇所への別々の追記)。
- `kTable` の行数は `static_assert` で `RIMDataId` の総数と自動照合されるため、
  行の追加漏れはビルドエラーになる。framework(共通機構)は不変。

## 5. DataStore で新しいデータを管理する流れ(最新値系の例)

```mermaid
sequenceDiagram
    participant RDI as RawDataInput(L1)
    participant Port as CentralInputPort(L2)
    participant Buf as CurrentValueBuffer
    participant Disp as CurrentValueDispatcher
    participant Reg as CurrentValueRegistry
    participant Cap as CapabilityLayer(L3)

    RDI->>Port: PostCurrentValueInput(item)
    Port->>Buf: post(item) （id別に最新値・dirty）
    loop 周期実行
        Disp->>Buf: takeUpdatedValues()
        Buf-->>Disp: 更新item群
        Disp->>Reg: Apply(item)
        Note over Reg: DomainForId(id)で副ドメイン判定<br/>変化あれば RegistryDomain を返す
        Reg-->>Disp: optional<RegistryDomain>
    end
    alt 変化あり
        Disp-->>Cap: notifyUpdated(domains)
    end
```

**新データを L2 に足す開発手順(最新値系)**:
1. `CurrentValueRegistry.cpp` の `kDomainTable`(テーブル駆動)に `id → 副ドメイン` を1行追加。
2. `CurrentValueRegistry.MakeSnapshot` と `Snapshot.hpp` の副Snapshot にフィールド追加。
3. 新副ドメインなら `RegistryDomain.hpp` にビット追加 + `MachineRegistry.Capture` の
   `kDomainCurrentAll` に含める。
4. L3 の `ICapabilityBuilder` が新フィールドを参照して判定。

> Adapter 側(§4)と DataStore 側(本節)は**独立して**変更できる。境界は `RIMDataItem`(id/value/context)。
