## 1. 概要

**FMとは：** 異常コードの状態遷移（ACTIVE → HEALED → NONE）を管理するモジュール。異常情報リストはFMが保持し、状態変化のたびにコピーを情報系へ通知する。機能制限・クリア条件の判断はしない。

読み手：
- 情報系の設計者
- FMのAPIを呼び出すモジュール（ユニット制御・機能制御・通信インフラ・消耗品管理・CLM）の設計者
- CFG提供者

## 2. 用語集

| 用語 | 意味 |
|------|------|
| ACTIVE | 異常が発生中の状態 |
| HEALED | 異常の原因が解消したが、まだNONE（未登録）になっていない状態 |
| NONE（未登録） | リストに登録されていない状態。コード通知を受ける前、またはクリア後の状態。 |
| 自動クリア | ヒーリング通知時にHEALEDへ遷移した後、自動クリアテーブルに登録されているコードをCLMを経ずにNONE（リストから削除）へ遷移させるCFG設定 |
| 即HEALED遷移 | ACTIVE登録直後にHEALEDへ遷移させるCFG設定。ヒーリング通知を待たない |
| 根本原因フィルタ | 根本原因コードがACTIVEの間、派生コードの登録を抑制するCFG設定 |
| 異常情報リスト | FMが保持するACTIVE/HEALEDコードの一覧 |

## 4. 制約事項

### やること・やらないこと

**やること**
- 異常コードの状態遷移決定
- 情報系への異常情報リストのコピー通知
- 根本原因フィルタ・重複チェック
- 異常情報リストの保持（追加・更新・削除）

**やらないこと（スコープ外・他コンポーネントの責務）**
- 機能禁止の判断（FLMの責務）
- クリア条件の判断（CLMの責務）
- UI表示、機械停止の指示

### クリアの発行ルール

クリアが発生するのは以下の2ケースのみ：

- CLMからのクリア要求を受けたとき
- ヒーリング通知受信後、HEALEDへ遷移したコードがCFGの自動クリアテーブルに登録されているとき

### 根本原因フィルタのルール
- 根本原因によりフィルタされる派生の異常コードを、別途根本原因に登録しない。FMは、これを階層的に管理はしない。

## 5. 接続先

### FMが受け付けるAPI

| API | 呼び出し元 | 内容 |
|---|---|---|
| 発生異常コード通知 | ユニット制御 / 機能制御 / 通信インフラ / 消耗品管理 | 新規異常コードをACTIVEとして登録する |
| ヒーリング通知 | ユニット制御 / 通信インフラ / 消耗品管理 / CLM | 指定コードをHEALEDへ遷移させる。HEALEDへ遷移したコードが自動クリア対象の場合は続けてNONEへ遷移させる |
| クリア要求 | CLM | 指定コード（1件）をNONE（リストから削除）に遷移させる |

### FMから呼ぶ接続先

| 接続先 | 接続方式 | 用途 |
|---|---|---|
| 情報系 | CFG登録のAPIハンドラ経由 | 異常情報リストのコピー通知 |

## 6. 機能概要

### 処理フロー

| 受信イベント | チェック・判断 | 内部処理・情報系通知 |
|---|---|---|
| 発生異常コード通知 | ①根本原因フィルタ → ②重複チェック → 通過で登録 | リストにACTIVE追加。即HEALED遷移テーブル該当なら続けてHEALED更新。→ 情報系へコピー通知 |
| ヒーリング通知 | 自動クリアテーブルを確認 | ACTIVE状態をHEALEDへ更新する。その後、自動クリアテーブルに登録されている場合はNONEへ遷移しリストから削除する。→ 情報系へコピー通知 |
| クリア要求（CLM） | 未登録（NONE）ならno-op | リストから削除。→ 情報系へコピー通知 |

### 状態遷移

| 遷移 | トリガー | 条件 |
|---|---|---|
| NONE → ACTIVE | 発生異常コード通知 | フィルタ通過・重複なし |
| ACTIVE → HEALED | 発生異常コード通知直後 | 即HEALED遷移テーブルに登録済み |
| ACTIVE → HEALED | ヒーリング通知 | - |
| HEALED → NONE | ヒーリング通知 | 自動クリアテーブルに登録済み |
| HEALED → NONE | CLMからのクリア要求 | HEALED状態であること（未登録はno-op） |

**コードの生存期間について**

リスト上に存在する状態は常にACTIVEまたはHEALEDのどちらかである。クリア後は即座にNONE（未登録）に戻る。

```text
[NONE]
   ↓ 発生異常コード通知
ACTIVE
   ↓ ヒーリング通知
HEALED
   ↓ CLMのクリア要求
[NONE]

[NONE]
   ↓ 発生異常コード通知
ACTIVE
   ↓ ヒーリング通知
HEALED
   ↓ ヒーリング通知（自動クリアテーブル登録済み）
[NONE]
```

## 7. 情報系への要件

情報系はFMから呼ばれる以下のAPIを実装し、FMの初期化時にCFGへ登録すること。

### 実装すべきAPI

| API | 呼び出しタイミング | 情報系の責務 |
|---|---|---|
| 異常情報リスト通知API | FMの状態遷移後（全変化時） | 受け取ったリストのコピーを登録コールバックへ通知する |
